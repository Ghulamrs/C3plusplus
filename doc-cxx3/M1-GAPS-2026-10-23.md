# M1: the self-compile gap list, measured on the Windows box, 2026-10-23

**What was measured.** Stage 0 is `cxx3-msvc.exe`, built by cl through `msvc\build.cmd` from
`6b6154f`. It compiled each of the 60 files in `src/` for x86_64-windows with `-keep-going=500`
(`tools/windows/self-compile.cmd`). There were two runs:

- **plain**: only cxx3's own `include/` and `lib/`.
- **with stand-ins**: measurement-only headers first on the path for `<unordered_map>`, `<mutex>`,
  `<atomic>`, `<thread>`, `<chrono>`, `<cerrno>` and `<deque>`, so that every file reaches the
  parser. The stand-ins are not in the tree and are not the fix; the fix is real headers in
  `include/` (design section 8).

| run | files compiled | errors | distinct sites |
| --- | --- | --- | --- |
| plain | 3 of 60 (`Operator.cpp`, `OptTable.cpp`, `Type.cpp`) | 530 | 236 |
| with stand-ins | 4 of 60 | 1,611 | 1,180 |

The Mac preview, taken with `-arch x86_64-windows`, gave 3, 4, 1,609 and 1,178. The two hosts
agree, so the list is about the language and the library, not the host.

**Most of the 1,611 errors are knock-on errors, so the counts below are not the work.** A class
whose body stops at one bad declaration loses every member after it. The member functions defined
out of line then report "'Parser' declares no member 'X'" (694 sites: `Parser` 366, `Tms6747` 116,
`X86_64Linux` 86, `Arm64Darwin` 51, `Optimizer` 41, `Preprocessor` 22, `MasmCodeGen` 12), and
"'X' was not declared" (212 sites, such as `Stream`, `src_` and `types_`). Each root below lists
what it takes down. When a root is fixed, the run should be repeated, because the next layer only
shows once the one above it compiles.

## Where it stands, later on 2026-10-23

**60 of 60 files in `src/` compile for x86_64-windows, with no stand-ins**, measured on the Mac with
`-arch x86_64-windows -keep-going=500` (the box's run is the next step, below). The list below is the

| step | files compiling | what it took |
| --- | --- | --- |
| the morning | 3 | - |
| L1 `std::function` | 46 | a function type as a template argument, and `<functional>`'s `std::function` |
| headers, L2-L14, B1-B6 | 56 | `<unordered_map>`/`<unordered_set>`, `<mutex>`, `<atomic>`, `<thread>`, `<chrono>`, `<ratio>`, `<cerrno>`, `<deque>`, `<regex>`; the language roots one by one, each with its case |

| the last three | 60 | below |

**The last three, and why they were worth more than three files.**

- **`OptPipeline.cpp`: a template binding that leaked.** Ranking `vector<unique_ptr<Pass>>::push_back`
  tried a conversion into `unique_ptr<Group> &&`, which instantiated `unique_ptr<Group>`'s converting
  constructor template with `U = Pass`. Its body cannot be built, the trial threw, and the class's
  `T = Group` was never unbound - so the next body replayed read `T` as `Group`. The bindings are put
  back by a destructor now (`Parser::BoundParams`). A silent wrong type wherever a ranked candidate's
  body failed.
- **`ParserTopLevel.cpp`: a use that skipped the deferral.** A constructor template ranked and not chosen
  defers what its body uses (`candidateUses_`); `constructMember` marked its chosen constructor used
  directly, so a `pair` constructor never called made `vector<unique_ptr<Expr>>`'s copy constructor
  "used". It goes through `noteUsed` now. Then `map::operator[]` copied a default value into its
  element, which a move-only mapped type cannot take ([map.access]/1); it moves it in now, in `map` and
  `unordered_map`.
- **And under that, a fault older than M1**: the implicit move constructor moved a `const` member with
  the member's move constructor, which cannot take `const K &&` - the copy constructor is the one that
  does ([class.copy]/15). A map element, `pair<const Key, V>`, met it once elements were moved in.
- **`Driver.cpp`**: `std::ofstream` and `std::ifstream` by a `std::string` name, and `std::atexit`.

**R6.4's helper exists now.** `make_owned<T>(args...)` in `Ast.h` holds the one `new` the memory rule
allows; the Windows exception work's new nodes are made by it, and so are the `ExprStmt`s of
`ParserStmt.cpp`, which takes the count from 1104 to 1068.

**Known, and not closed: a candidate's body is instantiated to rank it.** clang declares a member template
specialization and instantiates its body only when chosen. Here the body is replayed during ranking,
with what it uses deferred and a failure dropping the candidate - right for every program measured, but
a body that fails for a reason [temp.deduct]/8 does not cover drops a candidate the standard keeps.
`<thread>`'s constructor template carries an `enable_if` for that reason.

**What is next.** Assemble and link the 60 on the Windows box (`tools/windows/self-compile.cmd`), run the
compiler that makes, and compare what it emits with what `cxx3-msvc.exe` emits for the same input - stage 2.

## Stages 1 and 2 on the Windows box, the evening of 2026-10-23

**cxx3 compiles itself on Windows, and the result compiles itself to the same code.**
`tools/windows/self-host.cmd`: stage 0 is `cxx3-msvc.exe`, built by cl; it builds every source in `src/`
into `cxx3-stage1.exe`; stage 1 builds `cxx3-stage2.exe`; and each of the 60 sources' assembly from
stage 1 and from stage 2 is compared byte for byte, the clock pinned (`-D__DATE__`, `-D__TIME__`, which
`-version` prints). **60 of 60 the same**, at `3b6475d`.

Getting there took eight faults, every one in what cxx3 compiles rather than in the self-host's own
scaffolding, and every one with its case. In the order the stages met them:

| fault | what it did | case |
| --- | --- | --- |
| a `constexpr` function was not inline | `opt::bit`, `opt::frameReg` in an optimizer header were strong symbols in 25 objects: 48 LNK2005 | `constexpr-function-mergeable` |
| a virtual call's class result was not elided | the call is a comma (object address saved, then the call); the declaration bound `T &&` to a byte copy and destroyed the slot - Driver's `backend_->codegen()` handed back a freed code generator | `virtual-call-result-elided` |
| a scalar `?:` destroyed both arms' temporaries | `c ? f(a + b) : g(a + b)` destroyed a string never built - a free of a stack address | `conditional-arm-temporaries` |
| a class returned by value was built in the callee and moved as bytes | a returned `std::map` named its sentinel in a dead frame; now `return T(...)`, `return f()` and the named return value (NRVO, as clang decides it) are built in the caller's storage and anything else is moved there | `return-self-referential` |
| a `const` local returned was moved | it binds no `T &&`; [class.copy]/32's rvalue try fails and it is copied | in `return-self-referential` |

**Two more were found on the way and are Itanium's, not Windows'**: `std::basic_string` is `Sb` and
`std::allocator` `Sa` in an Itanium name, which cxx3 spelt `St12basic_string` (no object naming
`std::string` linked with clang's); and `<thread>` declared `this_thread::sleep_for` and `yield` without
defining them.

**How the last three were found, since the box could not show them.** Each crashed only outside a
debugger - cdb attached, the run succeeded - so the same 57 sources were built by cxx3 for arm64 on the
Mac, with `Driver.cpp`, `main.cpp` and `Preprocessor.cpp` (the POSIX-bound three) compiled by clang over
cxx3's own `include/`; the two link, the ABI being the platform's, once `Sb` was right. That arm64 stage 1
failed on nearly the same files, and a signal handler printing `backtrace_symbols`, `atos` against its
DWARF, and a frame checker over the emitted assembly (every `x29` offset against the frame its prologue
allocates) found the lambda fault in an hour. Built again, the arm64 stage 1 emits the same
x86_64-windows assembly as stage 0 for all 60 sources (`Driver.cpp` differing by `__TIME__` alone).
None of this is committed: it is a debugging aid, the Windows box remains where self-hosting is measured.

**And stage 2 is a working compiler, not only a consistent one**: the Windows case suite built by it
(`CXX1_CASES_COMPILER` names the compiler for `tools/windows/run-cases.cmd`, GNU spelling) - 606 programs
print their recorded output and 336 refusals are refused as recorded, none differing.

**What is next**: the MASM spelling and -O2 through stage 2, and the same stages on Linux and macOS, which
need `lib/` to declare the POSIX calls `Driver.cpp`, `main.cpp` and `Preprocessor.cpp` make.

input it leaves it as it was); `<thread>` starts a POSIX thread with 8 MB of stack, as Windows threads

the case. Two traps cost time and are worth the line: an object left stale after a header changed

crash was the sign of it.

**On the Windows box, at `a69d529`**: `self-host.cmd` 60 of 60; and stage 2 passes the case suite through

## 5. Order of work

1. **L1, `std::function`.** It is first by every measure: 43 files, and it hides most of what is
   behind it. It needs both halves: the language feature (a function type as a template argument)
   and a `<functional>` that has `std::function`. The library half is a design question, because
   `std::function` owns its target and so allocates; R6.6's memory rule should decide where.
2. **The headers in section 1**, `<unordered_map>` and `<mutex>` first: 25 files between them.
3. **L2, L3, L5 and L8**: each breaks a whole class or a header that many files include.
4. **B1-B6 and S1**: small, and each one ends a known cluster.
5. **L4, L6, L7, L9-L12**: local, one function or statement each.
6. **Measure again.** The rerun is `tools/windows/self-compile.cmd <root>` on the box, with and
   without the stand-ins, then the grouping above. Expect a second layer once the classes in L1
   and L2 compile whole.

## How the numbers were made

`self-compile.cmd` writes `selfout\<file>.err` and `.rc` on the box. The two `selfout` folders were
copied back, and every error was read in its two formats: the preprocessor's
`file:line: source / ^ message` and the parser's `file:line:col: error: message`. Errors were
grouped by message with names and numbers blanked, and each group was traced to the first
declaration that failed in the header or file it came from. A site counts once however many units
include it. The stand-in headers are measurement scaffolding and are not committed.
