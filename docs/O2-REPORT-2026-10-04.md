# cpp11 -O2 on the C6747: RIDE 4.7 as installed, against CCS 5.5 and CCS 7.4 - 2026-10-04

**What was run.** The cpp11, asm6x, lnk6x and vm6747 that the RIDE 4.7 installer put on each box
(`C:\Program Files\RIDE 4.7\bin` on Windows, `/opt/ride-4.7/bin` on Linux; cpp11 1.5, sealed
03-10-2026), compiling at -O2 every C6000 test case (`tests/cases`, 340 after the exemptions below),
the six kernels, five small programs, the RIDE examples as installed (Sample, **SampleExt**, Hello,
the four `cpp-*` projects, three programs, the 16-file compilerpp project reading `sample.cpp`) and
the Compiler++ harness (ten workload files, one simulator run each). The same sources built by
TI's cl6x 7.4.4 (CCS 5.5) at -O2 on both boxes and cl6x 8.2.2 (CCS 7.4) at -O2 on Windows.
Every build run on **CCS 5.5's C6747 cycle-accurate simulator** (cycle.Total) and cpp11's also on
VM6747. Nothing ran on the Mac.

**The oracle**, as instructed: cl6x 7.4.4 on the CCS 5.5 simulator, for output and for speed. Where
7.4.4 cannot build a program - it is C++03, and 76 test cases are C++11 - the case's recorded
output (clang's) stands in, and the table says which.

**Exempt**: the 16 `lambda*` cases, at the user's request. **Not for this target**: 13 cases (a
`.notarget` naming tms6747, or written for a 64-bit `long`).

## To mend in a future version

1. **RIDE 4.7's installer ships an LNK6x without the `.init_array` and zero-fill fixes** (lnk6x.exe
   dated 02-10; the fixes landed 03-10). Static constructors and destructors do not run, and one
   program dies at 0x98: array-destructor-only, array-static-storage, dynamic-init,
   dynamic-init-const, dynamic-init-reference, dynamic-init-scalar, global-constructor,
   static-base-pointer, template-static-data-member-ctor, ctor. Rebuild the installers with the
   current LNK6x.
2. **A thrown pointer reaches the handler one dereference short on TI's runtime**: throw-pointer,
   throw-class-pointer-ms - the right handler, the exception object's address where the pointer
   should be. VM6747 follows cpp11's convention and so hides it. Every level, not -O2.
3. **A float initialised `{1.0}` prints 0 on TI** (narrowing-allowed, `f` and `dd`; `big`, also a
   float, is right). VM6747 prints 1. Every level.
4. **`numeric_limits<double>::infinity()` prints `+inf` through TI's runtime** where clang prints
   `inf` (template-nontype-numeric). Every level.
5. **VM6747 cannot run cl6x -O2 code**: `SPLOOPW` unknown, a `STDW` offset it refuses, a branch
   issued while another is pending. So cl6x is compared on the TI simulator only.
6. **VM6747 writes CRLF on Windows**; **`lnk6x --version`** is not an option.
7. **cl6x is C++03**, so 76 test cases (C++11) have no TI build; `smart.cpp` neither.
8. **The C program `structs.c`** converts `const void *` to `T *` without a cast - legal C, and
   cpp11 is right to refuse it as C++.
9. **Running the simulator**: Linux thrashed with no swap and one JVM held for hundreds of runs
   (2 GB of swap and a fresh JVM every 40 runs fixed it); 12 lanes at once on Windows and 2 on Linux
   lose some starts to the debug server (retried automatically now).
