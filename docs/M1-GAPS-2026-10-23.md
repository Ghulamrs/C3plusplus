# M1: the self-compile gap list, measured on the Windows box, 2026-10-23

**What was measured.** Stage 0 is `cxx3-msvc.exe`, built by cl through `msvc\build.cmd` from
`6b6154f`. It compiled each of the 60 files in `src/` for x86_64-windows with `-keep-going=500`
(`tools/windows/self-compile.cmd`). There were two runs:

- **plain**: only cxx3's own `include/` and `lib/`.
- **with stand-ins**: measurement-only headers first on the path for `<unordered_map>`, `<mutex>`,
  `<atomic>`, `<thread>`, `<chrono>`, `<cerrno>` and `<deque>`, so that every file reaches the
  parser. The stand-ins are not in the tree and are not the fix; the fix is real headers in
  `include/` (design section 8).

| run | files compiled | errors | distinct sites |
| --- | --- | --- | --- |
| plain | 3 of 60 (`Operator.cpp`, `OptTable.cpp`, `Type.cpp`) | 530 | 236 |
| with stand-ins | 4 of 60 | 1,611 | 1,180 |

The Mac preview, taken with `-arch x86_64-windows`, gave 3, 4, 1,609 and 1,178. The two hosts
agree, so the list is about the language and the library, not the host.

**Most of the 1,611 errors are knock-on errors, so the counts below are not the work.** A class
whose body stops at one bad declaration loses every member after it. The member functions defined
out of line then report "'Parser' declares no member 'X'" (694 sites: `Parser` 366, `Tms6747` 116,
`X86_64Linux` 86, `Arm64Darwin` 51, `Optimizer` 41, `Preprocessor` 22, `MasmCodeGen` 12), and
"'X' was not declared" (212 sites, such as `Stream`, `src_` and `types_`). Each root below lists
what it takes down. When a root is fixed, the run should be repeated, because the next layer only
shows once the one above it compiles.

## 5. Order of work

1. **L1, `std::function`.** It is first by every measure: 43 files, and it hides most of what is
   behind it. It needs both halves: the language feature (a function type as a template argument)
   and a `<functional>` that has `std::function`. The library half is a design question, because
   `std::function` owns its target and so allocates; R6.6's memory rule should decide where.
2. **The headers in section 1**, `<unordered_map>` and `<mutex>` first: 25 files between them.
3. **L2, L3, L5 and L8**: each breaks a whole class or a header that many files include.
4. **B1-B6 and S1**: small, and each one ends a known cluster.
5. **L4, L6, L7, L9-L12**: local, one function or statement each.
6. **Measure again.** The rerun is `tools/windows/self-compile.cmd <root>` on the box, with and
   without the stand-ins, then the grouping above. Expect a second layer once the classes in L1
   and L2 compile whole.

## How the numbers were made

`self-compile.cmd` writes `selfout\<file>.err` and `.rc` on the box. The two `selfout` folders were
copied back, and every error was read in its two formats: the preprocessor's
`file:line: source / ^ message` and the parser's `file:line:col: error: message`. Errors were
grouped by message with names and numbers blanked, and each group was traced to the first
declaration that failed in the header or file it came from. A site counts once however many units
include it. The stand-in headers are measurement scaffolding and are not committed.
